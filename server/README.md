# HAHN Heroes online server

Published app entry: /_nexus-test/ → Squad → Online Squad HQ.

Eight server-controlled room modes: ODIN; Nexus Word Rush (Tapple); Shadow Signal; Memory Flip; Trivia Clash; Pattern Pulse; Word Scramble; Spot the Difference. Private 8-character room codes, 2–8 players (Shadow requires 3), 24-hour expiry, turn timers, optimistic concurrency, and reconnect from the same browser. Changes are polled every 1.5 seconds. ODIN includes Skip, Reverse, +2 and Wild; hands wrap to keep every card available without horizontal scrolling. Word Rush starts with curated Animals and Foods dictionaries. Trivia uses a shared general question set; solo grade-specific learning remains available separately.

Device identities are random 256-bit secrets stored locally, hashed on the server. No names, email addresses, photos, or messages are collected by this feature. Generated aliases are used in rooms. Custom authentication is checked inside the edge function, so platform JWT verification is intentionally disabled. Do not expose service-role credentials. All database tables deny public clients; only the authenticated server can query them. The two RPC functions are service-role-only and SECURITY INVOKER.

Online inventory is authoritative and separate from historical device-only cards, whose ownership cannot be verified. Each online hero receives Lantern, Compass and Scroll starter copies. Finished squad rounds award a fragment once per room per player. Milestones at 7/12/20/30 completed rounds award Rare/Epic/Legendary/Mythic cards. Local progress and solo rewards remain available in the original Vault. Clearing browser data loses the online device identity; cross-device account recovery is not implemented.

Trading: complete offers shown to both players, exact revision confirmation, changes reset both confirmations, maximum 12 copies per offer, row locking and an atomic transaction validate and exchange ownership. Values: Common 1, Uncommon 2, Rare 4, Epic 8, Legendary 16, Mythic 32. A copy scores 75% if the owner retains another copy of that type after the proposed exchange. Ratio above 1.5 requires both heroes to acknowledge an uneven-trade warning. Ratio at least 3 is blocked. No exchange occurs before both exact offers are confirmed. These initial thresholds are configurable in schema.sql and index.ts and were selected during this implementation, not previously approved numeric requirements.

Live verification: all eight room modes started with independent sessions; nonmembers rejected; hidden deck, hands, roles and answers redacted; turn and stale-revision checks; reconnect; exact trade confirmations; confirmation reset; non-owner card rejection; atomic exchange; completed-trade rejection; uneven acknowledgment; extreme block; ownership preserved on rejection. Local game-rule and DOM integration checks passed. No browser visual QA was available for the static preview.

Source files: schema.sql, index.ts, games.mjs. Changes must be deployed to Supabase as well as published to the Site. Execute schema.sql once when provisioning a new empty project. The current project's migration has already been applied. The edge function is named nexus. Endpoint and public publishable key are in online.js; those are safe to ship. Secrets live only in Supabase runtime variables.
